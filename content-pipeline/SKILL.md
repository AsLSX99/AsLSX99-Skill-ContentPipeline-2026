# 内容生产流水线（Content Pipeline）

流水线的价值在于**把体力活和判断力分开**：选题、素材、排版、分发是可自动化的体力活；审稿、改稿、个人风格是必须留给人的判断力。这条工作流的设计红线是——**干掉体力活，绝不外包判断力**：跳过人工审稿的号，活不长。

## 何时进入本工作流

- 用户要写/发一篇或多篇内容（公众号、博客、知乎、Newsletter、小红书）
- 用户抱怨写作流程耗时（找选题、翻素材、调格式占了大头）
- 用户发来一篇流程教程/效率文章，要求提炼成 SKILL
- 用户已有零散提示词，要求整理成可复用的流水线

缺的要素用默认值补齐继续：平台默认公众号、字数默认 2500、频次默认日更。一次只追问最关键的一个问题：**你的领域是什么**（选题与口吻都从这里长出来）。

## 核心模型：五环节 + 三件套

```
① 选题 → ② 素材 → ③ 初稿 → ④ 排版 → ⑤ 分发
  ↑__________ 质量门禁 G1–G4 + 数据回流 __________↑
```

每个环节的产出 = **参数化提示词 + 质量门禁 + 失败回退**三件套。任何一环只给提示词不给门禁，就是把翻车留到下游。

## 三件套详解（每个环节都按此展开）

### 1. 参数化提示词

提示词里的**领域、字数、口吻、数量、平台**必须是占位符，不是写死的示例值。硬编码的提示词换一个领域就废了，这是一次性教程和可售卖资产的区别。

```
搜索【{领域}】最近24小时的热门话题，结合【{信源列表}】，
给出{N}个选题。每个选题包含：一句话角度、目标读者痛点、差异化切入点、
预估写作难度（1-5）。输出为表格，按综合评分降序。
```

### 2. 质量门禁

每环节一个门禁（G1 选题 / G2 素材 / G3 初稿 / G4 成品），门禁分两级：

- **机器可判（硬规则）**：字数区间、必须项齐全、来源标注率 100%、禁词表命中数 = 0、Markdown 符号残留数 = 0。不达标自动打回重跑，不消耗人的注意力。
- **人工判（软规则）**：选题值不值得写、经历是否真实、口吻像不像本人。只留给人。

### 3. 失败回退

每环节写明"不达标怎么办"：打回重跑最多 2 次，仍失败则降级（如素材不足 2 条数据 → 降级为"观点 3 条 + 案例 3 个"并在初稿标注待补）。**流水线必须能在缺料时继续跑完并显式标记缺口**，卡死在半路的流水线比没有流水线更耗时。

## 判断力红线（写进流水线的硬约束）

1. **AI 出的是"骨架+毛坯"，人做"装修"**：初稿必经人工改稿环节（默认 15–20 分钟），改三件事——删 AI 腔句、换真实经历、砍长句。
2. **审稿与发布永远是人的动作**：流水线止步于"排好版的稿子 + 交付通知"。
3. **素材必须带来源**：无来源的素材摘要视为门禁失败。
4. **数据回流但不被数据绑架**：阅读数据只进选题评分，不进写作风格（追数据写出来的东西没有风格）。

## 执行顺序

1. 读 `assets/templates/pipeline-spec.md` 填好参数（领域/平台/频次/字数/口吻/通知方式）——这是总配置，后续所有提示词从它取值。
2. 按 01→05 逐环节落地，每环节产出三件套，过对应门禁。
3. 读 `references/07-platform-adapters.md` 把五个能力（定时、知识库、生成、文件、通知）接到用户实际用的 Agent 上。
4. 先跑通一天，再谈优化——**别一上来追求完美流程，哪里卡改哪里**。
5. 跑一周后按 `references/08-iteration.md` 做数据回流与提示词版本化。
