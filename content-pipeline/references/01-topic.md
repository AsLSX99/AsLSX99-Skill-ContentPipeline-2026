# 01 选题环节：让选题自己找上门

> 产出：每日选题清单（5 条，带评分排序）+ 选题门禁 G1。痛点基线：人工刷热搜/刷同行约 60 分钟，自动化后人的工作只剩 3 分钟——**挑**。

## 为什么这步值得自动化

找选题是典型的"低判断、高耗时"：刷一小时能做的事，边际价值极低，但不做又会断更。它是流水线的第一环，也是数据回流的入口（08 文档）。

## 参数化提示词

```
搜索【{领域}】最近24小时的热门话题，信源：【{信源列表}】。
给出 {N=5} 个选题，每个选题包含：
1. 一句话角度（不是话题，是切入方向）
2. 目标读者痛点（谁、在什么场景下被什么问题卡住）
3. 差异化切入点（与现有爆款文章的区别在哪）
4. 预估写作难度 1–5（5=需要大量数据/访谈）
5. 素材可得性 1–5（5=资料库里已有充足素材）
输出为表格，按【{评分权重}】降序排列。
```

### 关键参数

| 参数 | 默认 | 说明 |
|------|------|------|
| {领域} | 必填，追问用户 | 选题、口吻、信源全部由此派生 |
| {信源列表} | 知乎、微信搜一搜、新闻热点 | 按领域替换（技术类加 GitHub/HN，行业类加研报） |
| {N} | 5 | **必须写死数量**，不写会给 20 个等于没筛选 |
| {评分权重} | 痛点强度40% + 差异化30% + 素材可得性30% | 难度不进权重，只做一票否决（>4 且素材<2 则降级） |

### 加载选题专用 Skill（可选）

若运行环境有选题类 Skill（如"爆款选题侦查"类），在本环节之前加载；没有则直接用上方提示词，效果差距可通过收窄信源弥补。安装方式按各运行环境的 Skill 管理方式执行。

## 评分与排序

机器先打分排序，人只做三件事（3 分钟内完成）：

1. 删掉明显不值得写的（与定位不符、素材可得性 ≤1）
2. 调整顺序（结合当天热点时效）
3. 指定今天的主选题（默认第 1 条；也可另指定——下游素材环节要读这个"今日选题"）

## G1 选题门禁（机器可判）

- [ ] 恰好 {N} 条，不多不少
- [ ] 每条 5 个字段齐全（角度/痛点/差异化/难度/素材可得性）
- [ ] 角度是"切入方向"而非话题词（话题词如"AI 副业"不合格，"AI 副业里最先被替代的三种接单类型"合格）
- [ ] 按评分降序
- [ ] 难度 >4 且素材可得性 <2 的选题已标注"需外部素材"

不达标 → 打回重跑（最多 2 次），仍不达标 → 保留可用条目并显式标注缺口。

## 失败回退

- 信源抓取失败 → 降级为"基于资料库近 7 天存量 + 领域常青话题"出 3 条，并标注"无实时热点"
- 产出 >5 条 → 机器按评分截断，不把筛选压力丢给人

## 时间账

| 项 | 以前 | 现在 |
|----|------|------|
| 找选题 | 60 分钟 | 0（自动清单）+ 3 分钟人工挑 |

## 与其他环节的接口

- 输出给 02：**今日主选题**（一句话角度 + 目标读者痛点）
- 数据回流（08）：发文后阅读/在看/评论数据 → 写回每条选题的评分标签，校准下一次权重
