# 08 迭代：数据回流、提示词版本化与故障对照

> 跑通之后的三件事：让数据回流校准选题、让提示词可版本化、让故障可定位。

## 一、数据回流（只进选题，不进文风）

发文后把表现数据写回选题标签，校准下一次评分权重：

```markdown
## 选题回流表（每篇发布后 48h 填一次）
| 日期 | 选题 | 阅读 | 在看/赞 | 评论数 | 完读率(如有) | 标签 |
|------|------|------|--------|--------|-------------|------|
| | | | | | | {痛点类型}/{角度类型} |
```

**回流规则：**

1. 数据只更新"选题评分权重"（01 的 {评分权重}）——哪类痛点/角度持续表现好，权重上调
2. **数据不进写作风格**：追热点数据改文风 = 把号写成没风格的营销号
3. 样本 <10 篇时只记录不调权（小样本调权 = 过拟合昨天）
4. 评论区是选题金矿：读者问的问题直接进选题池

## 二、提示词版本化

每条提示词带版本号与变更记录，改一版记一版：

```markdown
## 提示词 vN（环节名）
- 变更：[改了什么] / [为什么改] / [改后效果]
- 生效日期：
```

- **一次只改一个变量**（字数/口吻/信源分开改），否则不知道哪个改动起效
- 改动依据来自：G 门禁打回记录 + 人工改稿清单的高频项（改稿清单里反复出现同一类问题 → 改提示词，而不是每次手动改）
- 你手上的初稿提示词是改了十几版的结果——**直接抄能用，但按自己领域再调几轮才是你的资产**

## 三、常见故障对照表

| 症状 | 失守位置 | 修复 |
|------|---------|------|
| 选题给一堆、没法挑 | 01 提示词没写数量/权重 | 写死 {N=5}，加评分排序 |
| 选题全是大话题没角度 | 01 未区分话题与角度 | 门禁加"角度非话题词"断言，示例正反对照 |
| 素材全是弱相关凑数 | 02 未写"宁缺毋滥" | 提示词加弱相关禁令 + G2 抽查 |
| 数据没口径没法用 | 02 数据要求不具体 | 强制"数值+口径+时间"三件套 |
| 初稿一股机器味 | 03 无禁词表/无真实经历位 | G3 禁词断言 + 改稿清单三件事 |
| 初稿编造填补素材缺口 | 02 缺口未传递 | G3"⚠占位必须保留"断言 |
| 排版后还有 Markdown 符号 | 04 未要求删符号/未扫描 | G4 正则扫描，残留=0 |
| 每次排版风格都不一样 | 04 没有 style profile | 先用旧文建档案，逐项比对 |
| 成品没人知道好了 | 05 无通知 | 接 C5，标题带选题名 |
| 流水线卡在半路 | 某环节无失败回退 | 每环节补"重跑×2 → 降级+标注" |
| 通知发了但缺口没说 | 缺口未随交付传递 | 通知模板含缺口字段 |
| 省了时间但内容更水了 | 判断力被外包 | 对照 SKILL.md 判断力红线：改稿与审稿不可省 |

## 四、基线测量（证明省了多少）

启动前先记录一周真实耗时（分环节计时），跑通后再记录一周：

| 环节 | 基线（分钟/篇） | 跑通后（分钟/篇） |
|------|----------------|------------------|
| 找选题 | [实测] | 目标 3（只挑） |
| 找素材 | [实测] | 0 |
| 写初稿 | [实测] | 目标 20（只改） |
| 排版 | [实测] | 目标 1 |
| 审稿+发布 | [实测] | 保留（人工，不计省） |

参考量级：基线约 3.7 小时/篇 → 跑通后约 25 分钟/篇。省下来的时间用于多写或去生活——工具的意义就是这个。

## 五、优化节奏

1. **先跑通，再优化**：别一上来追求完美流程，五环节跑通一遍，哪里卡改哪里
2. 第 1 周：只记录故障，不动提示词
3. 第 2 周：按故障频次改提示词（一次一个变量）
4. 第 3 周起：接数据回流，调选题权重
5. 每月：清理资料库、复盘回流表、给提示词归档版本
