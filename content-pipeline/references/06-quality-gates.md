# 06 质量门禁总表（G1–G4）

> 门禁的作用：把"机器能判的"全部拦在流水线内，把"必须人判的"显式交给人。没有门禁的流水线只是把翻车从生成环节推迟到发布环节。

## 设计原则

1. **硬规则机器判，软规则人判**——机器判的必须可执行（正则/计数/存在性检查），不接受"感觉不够好"这种门禁。
2. **门禁失败先打回，后降级**——打回重跑最多 2 次，仍失败走该环节的失败回退，**显式标注缺口继续跑**，不卡死。
3. **缺口传递不消失**——上游的缺口必须出现在下游提示词和最终通知里，静默吞缺口 = 门禁失效。

## 门禁总表

| 门禁 | 环节 | 机器可判（硬规则） | 人判（软规则） | 失败动作 |
|------|------|-------------------|---------------|---------|
| G1 | 选题 | 恰好 N 条；5 字段齐全；角度非话题词；评分降序 | 值不值得写；与定位是否相符 | 重跑×2 → 保留可用条目+标注 |
| G2 | 素材 | 三板块齐全；来源标注率 100%；数据含数值+口径+时间；单条引用<40字 | 素材是否真的相关 | 换关键词重跑×1 → 降级配比+⚠缺口 |
| G3 | 初稿 | 标题数=NT；禁词命中=0；开头无套话；字数±10%；小节数达标；来源标注；缺口未被编造 | ≥3处真实经历；口吻像本人；每节有带走的东西 | 重跑×2 → 降级（人重写开头+各节首段） |
| G4 | 成品 | Markdown残留=0；段落/金句/分隔线符合档案；无渲染差元素；HTML可打开 | 手机预览扫一遍；发布检查表 | 降级输出纯文本+规则说明 |

def check_draft(text, word_count=2500, sections=3, titles=3):

    assert len(titles_list) == titles          # 标题数

    assert count_h2(text) == sections
    assert "⚠" not in text or allow_gap       # 缺口占位保留

## 门禁执行位置

```
选题 --G1--> 素材 --G2--> 初稿 --G3--> 排版 --G4--> 分发
         ↑打回重跑（≤2次）↑        ↑人工改稿在 G3 之后、G4 之前
```

人工改稿是 G3.5（半自动门禁）：机器过 G3 硬规则 → 人执行改稿清单 → G4 验收排版。

## 常见门禁失效模式

| 失效 | 症状 | 修复 |
|------|------|------|
| 规则太软 | "检查文风是否自然"——机器放行一切 | 改为可数规则（禁词数、长句数、套话开头） |
| 缺口被吞 | 数据缺口在初稿里被编造填充 | G3 加"⚠占位必须保留"断言 |
| 门禁全在末端 | 发现问题时已到发布环节 | 分环节各设门禁，失败就地打回 |
| 人判项也想自动化 | "AI 审稿决定发不发" | 人判项永远留给人，见 SKILL.md 判断力红线 |
