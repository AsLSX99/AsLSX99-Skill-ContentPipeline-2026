# 05 分发环节：交付通知 + 发布检查表

> 产出：交付通知（带选题名）+ 发布检查表。流水线到此为止——**审稿、改稿、点发布永远是人的动作**。

## 设计：交付即通知，通知即流水线终点

稿子排好了怎么知道？流水线末尾挂一个通知环节，让人在电脑或手机上收到"今天的稿子出炉了"，打开审稿、进后台、发布、收工。

## 接线方式（按平台适配，见 07 文档）

任选其一，配置进 pipeline-spec 的 {通知方式}：

| 通知方式 | 配置 | 适用 |
|---------|------|------|
| 邮件（如 QQ 邮箱） | 连接邮箱连接器，授权一次；任务加"完成后把最终稿发送到 {邮箱}" | 手机即收即审 |
| 即时消息（企微/钉钉/Telegram/Bot） | 推送标题 + 正文前 200 字 + 成品文件链接 | 需要快速过一眼 |
| 文件目录 | 写入 {输出目录}/YYYY-MM-DD-{选题名}.md | 本地审稿流 |
| 会话内交付 | 当轮对话直接给出成品 | 手动触发模式 |

## 通知内容模板（参数化）

```
【{频次}】稿件出炉：{主选题}
- 字数：{字数}｜小节：{小节数}｜门禁：G1✓ G2✓ G3✓ G4✓（缺口：{无/N处}）
- 成品：{链接或附件}（HTML 预览 + 纯文本）
- 待你完成：审稿 → 改稿清单复核 → 发布
```

标题必须带选题名——通知的价值是让人**不打开就知道今天发什么**。

## 发布检查表（人执行，3 分钟）

- [ ] 改稿清单三件事已完成（删 AI 腔 / 换真实经历 / 砍长句）
- [ ] 真实经历部分无虚构、无泄露隐私/前东家信息
- [ ] 引用与数据的来源标注在成文中可见
- [ ] 标题兑现了正文承诺（不做标题党）
- [ ] 开头 3 行抓人、结尾问题想让人回答
- [ ] 预览在手机上扫一遍（小标题节奏、金句位置）
- [ ] 发布时间符合 {发布时间}（如早 8:30 选题 → 上午发）

## 失败回退

- 通知发送失败 → 重试 1 次 → 仍失败则写入 {输出目录}/PENDING.md 并在下次任务开头提醒
- 门禁有缺口项 → 通知正文显著标注 `⚠ N 处缺口待补`，不静默交付

## 职责边界（写进流水线的硬约束）

流水线止步于交付通知。以下动作**不进自动化**：

- 审稿、定稿
- 点击发布
- 与读者互动

跳过这一步的号，活不长——机器审不了"这篇还配不配以我的名义发出去"。

## 时间账

| 项 | 以前 | 现在 |
|----|------|------|
| 分发/交付 | 散落在各环节 | 通知自动，审稿+发布约 5 分钟（人工保留） |

## 与其他环节的接口

- 输入：04 排版成品 + G1–G4 结果 + 缺口清单
- 输出：通知 + 发布检查表；发布后数据进入 08 回流
